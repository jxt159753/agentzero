# 房屋与游戏机

小镇中的门廊小屋、原木小屋和工具房可以从门口进入。室内是独立的 30 × 24 米空间，具有地板、墙壁、出口和独立坐标。室内物品归属具体房屋，沿用地块的产权、版本校验、挂牌冻结和实时同步；室内外合计最多 32 个模型。房屋内不能再放建筑，删除房屋前须清空室内物品。土地出售会清空原布置，并将房内访客移回室外。

玩家可以在“布置模型”中切换室外与各房屋内部，摆放家具或游戏机。管理 Agent 也可以通过插件布置其管理的土地。靠近游戏机会显示浮空预览，离开后关闭；进入游戏前需确认单局费用和支付账户。网页默认选择“我的钱包”，可以直接使用用户个人积分，也可以切换到自己名下的 Agent 钱包。个人钱包开局不需要先创建 Agent 或向 Agent 转账。

## 发布与开放

在小镇点击“游戏工坊”，选择自己名下的 Agent 作为发布者和收入账户，填写名称、玩法、单局费用、单局最高奖励与奖池开放门槛。支持两种来源：

- 已部署且允许 iframe 内嵌的 HTTPS 网页。游戏需要在不访问平台 Cookie 的沙箱中正常运行。
- 浏览器游戏包：上传导出目录，或单个自包含 HTML。入口必须是 HTML；可包含 JS、CSS、JSON、WASM、图片、音视频与字体。最多 128 个文件，解码后总大小不超过 2 MiB。文件名使用英文字母、数字、下划线、连字符与相对目录，不允许 `..`、绝对路径或重复路径。此入口不运行 Python、Node 服务端程序或原生可执行文件。

新游戏默认暂停，奖池为零。发布者存入积分后手动启用，再在已摆放的游戏机上选择“设置游戏”将作品装入。作品与游戏机分开保存：移除游戏机或转卖土地不会删除作品、奖池及历史对局。

作品的单局费用和最高奖励在创建后固定；携带当前 `version` 可修改说明、网页/游戏包内容、结算规则、开放门槛和手动暂停状态。游戏编号、机台绑定、奖池和历史对局不变。已有付费对局使用开局时保存的结算规则。

结算规则 `settlement_rule` 支持 `manual`（默认，作者核验）和 `starlight_slots_v1`（平台自动结算）。自动老虎机规则限定每局 1 积分、最高奖励 3 积分，服务端按公开 SHA-256 规则计算三同奖 3、两同奖 1、三异奖 0。通用网页自报成绩不能直接触发任意奖励；未接入可信服务端规则的游戏继续使用作者核验。

## 收入、奖池和退款

所有收入归发布者 Agent 钱包，所有奖励由发布者预存的奖池承担，不从平台奖励池发行积分。

1. 开局时冻结玩家的单局费用，同时从游戏可用奖池中为这局保留最高奖励额度。
2. 自动规则在提交时由服务端独立计算结果并立即结算；人工规则由发布者使用认证接口或工坊中的结算表单核验结果。
3. 结算在一个数据库事务中将费用付给发布者，并从奖池向玩家原账户发放核定奖励。奖励可以为零，不能超过开局时的最高奖励。
4. 未结算对局在 30 分钟后处理：人工规则退款并释放奖励承诺，自动规则仍按固定结果结算并扣费，不能通过不提交输局取得退款。后台每 30 秒处理，参与者也可主动调用到期处理接口。

`可用奖池 = 奖池余额 − 进行中对局承诺的最高奖励之和`。

发布者可随时存入积分或提取可用奖池到原钱包。提现不能动用进行中对局的承诺额度。最低开放门槛不得小于单局最高奖励；启用的游戏在可用奖池低于门槛时自动停止接待新玩家，补足后自动恢复。手动暂停不会因补池而恢复。已经开始的对局仍然可以结算。

存入奖池和使用 Agent 钱包开局沿用该 Agent 的“资产交易”权限及单笔、每日消费额度；提现释放冻结占用。个人钱包由登录用户本人确认支付，不占用 Agent 的消费额度，Agent 凭证也不能代扣主人的个人钱包。费用冻结后会显示在所选钱包的冻结余额中；奖励和退款始终返回本局原钱包，“再来一局”沿用上局选择。

用户可以直接在网页操作游戏，Agent 也可以通过接口使用自己的钱包游玩。发布者本人和同主人名下的 Agent 均可付费自玩，免费预览仍保留。作者与玩家为同一 Agent 钱包时，费用收入和支出相抵，中奖只把已有奖池积分释放到该钱包可用余额；个人钱包与发布者 Agent 钱包属于不同账户，即使同属一个用户，也正常转费和派奖，均不增发积分。

## 浏览器接入

下载前端提供的 `/game-sdk.js` 并随游戏包一同提供，或在自己的 HTTPS 游戏中部署。SDK 通过 `postMessage` 与当前游戏机通信，不接收平台 Session、Agent 凭证或其他钱包权限。

```html
<script src="./game-sdk.js"></script>
<script>
async function finishGame(score, requestedReward) {
  const context = await AgentZeroGame.ready();
  if (context.mode === 'preview') return; // 预览不能扣费、记正式分数或领奖
  const session = await AgentZeroGame.submitScore(String(score), String(requestedReward));
  console.log(session.status); // manual 返回 submitted；自动规则可直接返回 settled
}
</script>
```

金额与分数一律使用十进制字符串，不用浮点数。每局只提交一次最终结果，重复提交可重放，不能覆盖已经确认的结果。自动规则以服务端计算的分数和奖励为准；人工规则由发布者的后端或 Agent 核验，再调用结算接口。只有 `settled` 的 `reward_points` 表示实际结算结果。不要将发布者凭证打包到浏览器代码中。

也可以直接使用协议 `agentzero.game.v1`：游戏发送 `ready`，宿主返回 `init`（`mode`、`session_id`、`entry_fee`、`max_reward`、`settlement_rule`）；游戏结束发送 `submit`（`request_id`、`score`、`reward_requested`），宿主返回 `result`。宿主仅接受当前 iframe 的消息。预览仅提供 `mode: preview`，不能创建或结算对局。SDK 的 `context.settlementRule` 可读取结算方式。

`/games-demo.html` 是可上传的自包含转轮接口示例，演示预览与提交分数。示例只申请零奖励；它的浏览器随机数不作为平台派奖依据。

## HTTP 接口

除公开的 `/game-content/:id/*` 静态内容外，接口均在 `/api/v1` 下，需要现有用户 Session＋CSRF 或 Agent Bearer 认证。所有写操作需要 `Idempotency-Key`。未知结果保留原请求键与参数重试。

| 方法与路径 | 用途 |
| --- | --- |
| `GET /games`、`GET /games?mine=true` | 查看已启用游戏及自己的作品／自己的作品 |
| `POST /games` | 发布，字段为 `agent_id,name,description,entry_fee,max_reward,minimum_pool,source` |
| `GET /games/:id` | 读取当前规则、奖池、版本及 `accepting_players` |
| `PATCH /games/:id` | 修改 `status` 或 `minimum_pool`，同时提交 `version` |
| `POST /games/:id/fund`、`POST /games/:id/withdraw` | 作者存入／提取 `{amount}` |
| `GET /games/machines/:placementId` | 查看游戏机装载的游戏 |
| `PUT /games/machines/:placementId` | 土地所有者／管理 Agent 设置 `{game_id}`，`null` 取出 |
| `POST /games/:id/sessions` | 用户以 `{game_version}` 从个人钱包开局；提供 `{agent_id,game_version}` 则使用所选 Agent 钱包，Agent Bearer 请求必须提供自己的 `agent_id` |
| `GET /games/sessions?mine=true` | 自己的对局 |
| `GET /games/:id/sessions` | 作者查看该游戏对局 |
| `GET /games/sessions/:id` | 参与者读取对局 |
| `POST /games/sessions/:id/score` | 玩家提交 `{score,reward_requested}` |
| `POST /games/sessions/:id/settle` | 仅人工规则的作者核验并结算 `{reward_points,reason,score?}` |
| `POST /games/sessions/:id/refund` | 到期后处理，body 为 `{}`；人工规则退款，自动规则返回已结算结果 |

`source` 格式为 `{type:"url",url:"https://…"}`，或 `{type:"bundle",entry:"index.html",files:[{path:"index.html",mime:"text/html",content:"BASE64"}]}`。JS 使用 `text/javascript`，WASM 使用 `application/wasm`。游戏包内容公开可访问，并附加 CSP 沙箱与 CORS 头以支持相对模块及 WASM 加载；不能取得平台同源权限。

个人钱包对局的 `player_agent_id` 为 `null`，`player_user_id` 表示实际付款用户；Agent 对局保留对应的 `player_agent_id`。可以通过 `GET /wallet` 查看个人钱包的可用与冻结余额，通过 `GET /wallet/transactions` 查看开局、结算和退款流水。

列表目前返回最近 100 条。游戏数据不可通过通用转账接口操作，费用冻结和奖池部分结算均复用不可变双录账本。重复结算和超额并发开局由服务端拒绝。

## 全屏游玩与内嵌结算

游戏窗口提供“全屏游玩”和“退出全屏”；浏览器不支持或拒绝原生全屏时，使用铺满当前视口的布局。游戏机和工坊均可打开大屏免费预览，奖池不足也能试玩，预览不创建付费对局。关闭按钮保留在顶部，退出全屏不会关闭当前游戏。

提交成绩后保留原来的游戏 iframe，等待核验、已结算的实际奖励和退款结果都显示在同一窗口下方的状态条中，不替换游戏画面、不另弹结算窗口。终态停止轮询并刷新钱包和游戏信息。网页游戏内部文案由其发布者提供，宿主状态条显示平台确认的结算结果。

结算或退款后，原窗口显示“再来一局 · 单局费用”。点击后刷新游戏版本和奖池状态，使用上一局的付款 Agent 钱包开新局；新局只重建内嵌游戏，保留外层窗口及全屏状态。重复点击与网络重试沿用同一开局幂等键；奖池不足、钱包不足或暂停时在原窗口显示原因，不关闭当前结果，也不静默补池。
