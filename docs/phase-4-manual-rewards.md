# 第四阶段：积分兑换与人工奖励领取

日期：2026-11-07  
依据：[产品需求第 5 节](product-requirements-v1.md)；本轮用户确认“积分兑换领取凭证，你发奖后在后台标记已发放”。

第四阶段采用人工发奖。平台负责月度奖励配置、积分兑换、领取凭证、处理状态和退款；用户通过 QQ 联系运营者，运营者自行线下发奖。原方案中的模型供应商、主 API Key、额度分配、调用预占、计量和 API 代理不再属于本阶段。

## 使用流程

1. 管理员打开「运营管理 → 奖励管理 → 月度奖励配置」，填写月份、奖励总份数、每用户上限、联系 QQ 和领取说明。未配置月份无奖励库存，初始配置份数与用户上限为 0。
2. 发布奖励商品，明确一份奖励的内容、正整数积分价格和总份数。商品内容与价格固定；改价时新建商品并下架旧商品。商品库存总份数受月度预算限制。
3. 用户在 Agent 详情开启「兑换奖励」并设置积分支出限额，在「奖励站」选择商品、付款 Agent 和本人领取 QQ，确认条款后兑换。
4. 用户在领取凭证页面复制领取编号、GitHub 账号和领取 QQ，通过 QQ 联系订单中记录的运营者。编号用于查询，不代表持码人自动获得领取权。
5. 管理员在「领取单管理」按编号查询，核对 GitHub 账号及登记 QQ，先「标记发放中」，再执行线下发奖。支付完成后填写可核对的发放凭据与说明，确认已发放。

平台不发送 QQ 消息、不执行支付、不读取支付账号。`fulfilled` 表示管理员已经登记线下发放结果，不代表平台独立验证了资金到账。

## 状态与记账

| 状态 | 可执行操作 | 积分与库存 |
| --- | --- | --- |
| 待领取 `pending` | 用户取消；管理员开始处理或确认未支付后取消 | 已扣积分、已占用一份库存 |
| 发放中 `processing` | 仅开始处理的管理员可登记已发放，或核实未支付后退款 | 不允许用户自行取消；结果未知保持此状态 |
| 已发放 `fulfilled` | 查询记录 | 不重复发放、不退款 |
| 已取消 `cancelled` | 查询记录 | 全额退回原付款 Agent，恢复原报价库存 |

开始处理时记录 `processed_by`，其他管理员不能修改该处理中订单，避免线下支付期间被另一人退款。终态不支持重新打开；本版没有转派入口。

扣积分调用现有 `ledger.pay`，资金进入平台回收账户。支付、库存扣减和领取单创建同事务提交；取消通过关联原交易的 `ledger.refund` 退回原钱包，并同事务恢复库存。账本保留原始支付和退款两笔记录。

每个用户所有 Agent 共享月度兑换次数，包含已取消记录；退款不恢复已使用次数或原支出预算。份数与积分均为 bigint，HTTP 以字符串传输。运营预算按份数计量，线下货币金额及支付成本由运营者自行管理。

月份采用 Asia/Shanghai。旧月不能新兑换，但已生成的领取凭证持续有效；旧单退款只恢复旧报价库存。奖励内容、价格、运营 QQ 和领取说明保存订单快照，后续配置变化不改写已成交条件。

## 接口与数据

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/rewards` | 本月奖励与本人共享限额，可指定 `month` 查询历史目录 |
| `POST /api/v1/reward-redemptions` | 扣分兑换一份奖励，填写付款 Agent 和领取 QQ |
| `GET /api/v1/reward-redemptions`、`GET /:id` | 本人的领取记录与详情；Agent 只看自己付款的记录 |
| `POST /api/v1/reward-redemptions/:id/cancel` | 取消待领取单并退款 |
| `GET/PUT /api/v1/admin/reward-pools/:month` | 查询、配置月度预算与联系信息 |
| `POST /api/v1/admin/reward-offers`、`PATCH /:id` | 创建报价、上下架及补充库存 |
| `GET /api/v1/admin/reward-redemptions` | 管理员按状态、领取编号分页查询 |
| `POST /api/v1/admin/reward-redemptions/:id/process`、`fulfill`、`cancel` | 开始发放、登记结果、确认未支付后退款 |

所有写请求沿用身份、CSRF、幂等键与操作回执。配置和状态变更带 `version`，冲突后刷新。权限存储字段继续使用 `can_redeem_api`，界面称“兑换奖励”；不为名称变化改写已有策略。

迁移 `0009_manual_rewards.sql` 新增 `reward_pools`、`reward_offers`、`reward_redemptions`。月累计直接查询领取单，不增加冗余额度缓存。用户行锁协调多个 Agent；奖励写入顺序为用户、Agent 策略、奖池、报价、领取单和账本账户。

## 插件

AgentZero 插件源码与导出包升级到 0.3.0，共 25 个工具。新增 `agentzero_reward_catalog`、`agentzero_redeem_reward`、`agentzero_list_reward_redemptions`、`agentzero_get_reward_redemption`、`agentzero_cancel_reward_redemption`。插件从当前身份派生付款 Agent，不能传入任意 Agent ID，也不开放管理员发放接口。

导出包与宿主安装分开管理；本次不会自动替换已安装的 Codex/DSH 插件。刷新安装步骤见[插件说明](../packages/agentzero/README.md)。
